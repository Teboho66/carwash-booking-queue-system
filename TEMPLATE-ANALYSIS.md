# Template Analysis and Selection

## 1. Overview

GitHub Projects provides a number of project templates that support different styles of software project management. For this project, the goal was to select a template that best supports Agile planning, task tracking, and iterative development for the Web-Based Car Wash Booking and Queue Management System.

The system already uses user stories, GitHub Issues, a product backlog, and sprint planning from previous assignments. Therefore, the selected project template needed to support visual workflow management and task progression across multiple stages of development.

---

## 2. Comparison of GitHub Project Templates

| Template | Typical Columns / Workflow | Automation Features | Suitability for Agile Methodologies | Suitability for This Project |
|----------|-----------------------------|---------------------|-------------------------------------|------------------------------|
| Basic Kanban | To Do, In Progress, Done | Minimal by default; manual task movement | Suitable for simple Agile workflows and visual task tracking | Good starting point, but requires customization for more detailed workflow stages |
| Iterative Development | Organizes work into repeated increments and cycles | Supports MVP-first development, works well for gradual feature expansion, aligns with sprint-based thinking | Less visually explicit on its own without a board structure | Suitable as a supporting development approach |
| Roadmaps | Supports planning of future work and higher-level direction | Useful for showing progression from MVP to future enhancements, helps communicate long-term scope | Less useful for day-to-day execution tracking | Suitable as a planning complement |
| Team Planning | Backlog, Ready, In Progress, Done | Supports roadmap-style planning and team coordination | Suitable for Agile planning where prioritization and task readiness are important | Suitable for sprint planning and backlog visibility, but may require additional workflow customization |
| Automated Kanban | To Do, In Progress, Done | Automatically moves issues and pull requests between columns based on status changes | Very suitable for Agile because it reduces manual tracking effort and supports continuous workflow updates | Strong option, especially for teams using linked issues and pull requests |
| Bug Tracker | New, Needs Review, Ready, Closed | Focuses on issue classification and handling | More suitable for maintenance and defect management than full Agile product delivery | Less suitable because this project is feature-driven, not primarily bug-driven |

---

## 3. Selected Template

The selected structure for this project is a **Kanban-based project board**, adapted from the GitHub Kanban style of workflow management.

Although GitHub offers several templates, the Kanban approach was the most suitable because it supports:

- clear visibility of work items
- movement of tasks through workflow stages
- alignment with user stories and sprint planning
- iterative delivery of features in MVP increments

---

## 4. Justification for Selection

The Kanban template was selected because it aligns best with the needs of the Web-Based Car Wash Booking and Queue Management System. This project is being developed incrementally, starting with core features such as registration, authentication, service browsing, booking, and virtual queue management.

A Kanban-based board is appropriate because:

- it provides a visual representation of task progress
- it supports Agile principles such as continuous flow and adaptability
- it works well with GitHub Issues created from user stories
- it allows backlog items to be prioritized and moved through stages of implementation

In this project, the board was further customized to reflect the actual workflow more accurately by including additional columns beyond the default structure. This makes it more suitable for tracking development, review, testing, and completion activities.

---

## 5. Conclusion

After comparing multiple GitHub project templates, the Kanban approach was the most suitable for this system. It supports the project’s Agile planning structure established in previous assignments and provides a practical way to manage linked issues, workflow stages, and progress visibility throughout implementation.
